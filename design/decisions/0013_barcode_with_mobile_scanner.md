# 0013 バーコードはアプリに登録した番号と照らし合わせ、読み取りは mobile_scanner を使う

- 状態: 採用
- 日付: 2026-11-01

## 状況

商品のバーコード（JAN コード）をカメラで読んで、アイテムを探したり登録したりしたい（仕様 F-20）。アプリは Flutter Web で、スマホのブラウザ（iOS Safari・Android Chrome）から使う。Cloud Functions は使わず、外部の有料サービスも使わない。

## 決定

- **読み取りには `mobile_scanner` パッケージを使う。** Web では、ブラウザの BarcodeDetector API が使えればそれを、使えなければ zxing-wasm（jsDelivr から読み込む）を使う。
- **読み取る種類は JAN（EAN）-13・JAN（EAN）-8・UPC-A・ITF-14。** 末尾のチェックデジットが合わないものは読み間違いとして無視する。UPC-A は先頭に 0 を付けて 13 桁にそろえる（`normalizeBarcode`）。
- **商品名の自動取得はしない。** 読み取った番号を、家族がアプリに登録した番号と照らし合わせるだけにする。登録されていない番号なら、新しいアイテムとして追加するか、既存のアイテムに登録するかを選ぶ。
- **1 つのアイテムに 10 個まで登録できる**（`items.barcodes` の配列）。同じ番号をほかのアイテムに登録することはできない（アプリで確認する）。
- **カメラが使えないとき（許可されていない・対応していない）は、番号を手で入力できる。**
- 既存のアイテムにバーコードだけを登録するときは、更新者・更新日時を変えない（在庫の状況が変わらないため。[0005](0005_purchase_does_not_change_updater.md) と同じ考え方）。編集シートで保存したときは、ほかの項目と一緒にこれまでどおり更新者を変える。

## 理由

- `mobile_scanner` は Flutter Web に対応しており、iOS Safari でも zxing-wasm で読み取れる。カメラの起動・権限の扱いもまとめて任せられる。
- 商品名を番号から調べるには外部の商品データベース（API キーや利用登録が必要なもの）が要る。家族で使う日用品は種類が限られ、一度登録すれば次からは読むだけで済むので、自動取得なしでも十分役に立つ。
- 同じ「トイレットペーパー」でも、買うたびに銘柄やサイズが変わることがあるため、1 つのアイテムに複数の番号を登録できるようにした。上限は、ルールでの検証とドキュメントの大きさを抑えるため 10 個にした。
- チェックデジットで確かめると、カメラの読み間違いや打ち間違いで違うアイテムに当たることを防げる。

## 影響

- BarcodeDetector API がないブラウザでは、初めて読み取るときに jsDelivr から zxing-wasm を読み込む。オフラインで読み込めない場合は、番号の手入力を使う。
- 同じ番号の重複はアプリで確認しているため、2 人がほぼ同時に同じ番号を別のアイテムに登録すると、重複が起こりうる（その場合、探したときは両方のアイテムが出る。編集シートから外せる）。
- 在庫一覧の検索は、入力がバーコードの番号と同じアイテムも出す（バーコードで探したときは、検索欄に番号を入れる）。
