# 0006 アイテムの並び順はユーザーごとに持つ

- 状態: 採用
- 日付: 2026-10-25

## 状況

PoC ではアイテムを名前の文字コード順に並べていたため、漢字の名前が読みの順にならず、目当てのアイテムを探しにくかった。並び順を手動で設定できるようにする。家族で 1 つの並び順を共有する方法と、各自が自分の並び順を持つ方法がある。

## 決定

- 並び順はユーザーごとに持ち、`users/{uid}.itemOrder` に「カテゴリ ID → そのカテゴリのアイテム ID を表示順に並べた配列」として保存する。
- 並べ替えは同じカテゴリの中だけ。並べ替えたカテゴリの配列だけを丸ごと書き換える（`saveCategoryOrder`）。
- 配列に入っていないアイテムは、その後ろに追加した順（`createdAt` の古い順）で並べる（`sortByMyOrder`）。
- 在庫一覧と買い物リストの両方で使う。読み仮名のフィールドは持たない。

## 理由

- 在庫一覧は各自が自分のスマホで見るので、並びが人によって違っても困る場面が少ない。見る場所や買い物のルートに合わせて、各自が並べられる。
- 誰かが並べ替えても、ほかの家族の画面が勝手に変わらない。
- 自分の `users` ドキュメントだけに書くので、アイテムの更新者・更新日時が変わらず、ほかの人の書き込みともぶつからない。
- アイテムに順番の数値を持たせる方式と比べて、カテゴリを移したアイテムは移動先の配列に入っていないため自然に末尾になり、削除したアイテムは表示時に無視するだけで済む。
- 件数が少ない（家族 5 人の日用品）ため、配列を丸ごと書き換えてもドキュメントの大きさ・書き込み回数とも無料枠に十分収まる。

## 影響

- 家族で同じ画面を見ながら「上から 3 番目」のように話すと、並びが違うことがある。
- 削除したアイテムやカテゴリの ID は、次にそのカテゴリを並べ替えるまで配列に残る（表示には影響しない）。
- `users` ドキュメントに書けるフィールドが増えるため、セキュリティルールの対象も合わせて更新している。
- 並べ替え・絞り込みをアプリ側で行う方針（[0003](0003_sort_on_client.md)）はそのまま。
