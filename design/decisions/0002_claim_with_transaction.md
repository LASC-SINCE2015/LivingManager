# 0002 担当宣言はトランザクションで先着優先にする

- 状態: 採用
- 日付: 2026-10-25

## 状況

重複買いを防ぐため、買い物リストで「買います」と宣言した人（担当者）を家族で共有する。ほぼ同時に 2 人が宣言した場合、単純な上書きだと後から保存した人が担当者になり、先に宣言した人は気づかないまま買いに行ってしまう。

## 決定

担当宣言・カゴ済みのチェック（`ItemsRepository.claim`）は Firestore のトランザクションで行い、読み直した時点でほかの人が担当していれば上書きせずに `ClaimConflicted` を返す。ほかの人の担当を引き継ぐのは、画面で確認ダイアログを出して、引き継ぐ相手の uid（`takeOverFromUid`）を明示したときだけにする。ほかの人のカゴ済みは引き継げない。

「やめる」「チェックを外す」も、自分の担当のときだけ変更するようトランザクションで確認する。

## 理由

- Firestore のトランザクションは、読んだドキュメントがコミットまでに変わると自動でやり直すため、先にコミットした人が必ず優先される。
- Cloud Functions を使わずに実現できる（[0001](0001_no_cloud_functions.md)）。
- 引き継ぐ相手を明示させることで、「確認ダイアログを見ている間に別の人が担当した」場合も上書きしない。

## 影響

- トランザクションはオフラインでは実行できず、「保存できませんでした」と表示される。仕様の「オフライン中の操作は接続が戻ったときに判定し直す」は**未実装**。
- 処理の流れは [sequences/shopping.md](../sequences/shopping.md)。
