# 0001 Spark プランで運用し、Cloud Functions を使わない

- 状態: 採用
- 日付: 2026-10-25

## 状況

家族 5 人で使うアプリで、運用費をかけたくない。Firebase の Spark（無料）プランでは Cloud Functions が使えない。

## 決定

Spark プランで運用し、サーバー側のコードは持たない。アプリは静的ファイルとして Hosting から配信し、データの読み書きはアプリから Firestore へ直接行う。

## 理由

- 利用者が少なく、Spark の無料枠で足りる。
- 必要な処理（担当の先着判定、購入完了の一括更新）は、アプリ側のトランザクション・バッチで実現できる。

## 影響

- データの整合はアプリ側の処理と Firestore のセキュリティルールで保つ。ルールのテストを重視する（app/firebase/tests/）。
- サーバー側でしかできない処理（定期実行、通知の送信、他人の操作を検知しての自動処理など）は作れない。例: 24 時間以上たった担当を自動で解除することはせず、画面で「（1日以上前）」と表示するだけにしている。
- 将来 Blaze プランに上げて Cloud Functions を使う場合は `app/functions/` を追加する（[folder_structure.md](../architecture/folder_structure.md)）。
