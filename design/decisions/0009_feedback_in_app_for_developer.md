# 0009 改善意見の一覧はアプリ内の別ページで、開発者だけが見る

- 状態: 採用
- 日付: 2026-10-25

## 状況

家族がアプリを使ってみた改善意見を送れるようにし、送られた意見を別の URL で一覧できるようにしたい（仕様 F-14 / F-15）。一覧の置き場所として、同じアプリの中の別ページにする方法と、Firebase Hosting の別サイト（別ドメイン）に管理用のページを作る方法がある。また、意見にスクリーンショットなどの画像を添付できるようにするかも決める必要がある。

## 決定

- 一覧は **同じアプリの中の別ページ** `/feedback` にする。下部のタブ（PC ではサイドナビ）には出さず、タブの外の独立したページとして開く。設定画面にも、開発者のときだけ導線を出す。
- 一覧を見て状態・メモを変えられるのは **開発者だけ**。一般の家族は、自分が送った意見とその対応状況だけを送信画面で見られる。開発者かどうかはページの中で判定し（`isDeveloperProvider`）、開発者でなければ一覧を読み込まない。
- 意見は **テキストのみ** とし、画像の添付はしない。

## 理由

- 同じアプリの中なら、ログイン・利用許可の判定・画面遷移（ログイン後に元のページへ戻る）などをそのまま使える。別サイトにすると、ログイン画面や設定値、デプロイの手順を二重に持つことになり、手間が大きい。
- 独立したページにしておけば、PC のブラウザで URL を直接開いて、広い画面で一覧できる（最大幅 960px で中央寄せ）。
- 画像を保存するには Cloud Storage が必要だが、新しく使い始めるには有料プランへの切り替えが必要になる。作成・運用を無料で行う方針（[0001](0001_no_cloud_functions.md) と同じく Spark プランの範囲で運用する）に反するため、添付はしない。
- 家族の意見を開発者だけが見る形にすると、ほかの家族に見られることを気にせず送れる。

## 影響

- 開発者かどうかの判定方法はリポジトリでは管理しない。
- 不具合の状況は本文で説明してもらう必要がある。送信時にアプリのバージョンを自動で記録して、調査の手がかりにする。
- 開発者でないアカウントでも `/feedback` の URL を開くことはできるが、「このページを見る権限がありません」と表示し、データは読み込まない。
