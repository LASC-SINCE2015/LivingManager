# 0010 利用するアカウントの追加は、アプリ内の依頼と開発者の承認で行う

- 状態: 採用
- 日付: 2026-10-25

## 状況

利用するアカウントを増やすには、これまで開発者がアカウントのメールアドレスを聞き、Firebase コンソールで許可リストに手で登録していた。手間がかかり、メールアドレスの打ち間違いも起こりうる。アプリの中で「追加してほしい」と依頼し、開発者がアプリから承認できるようにしたい（仕様 F-16 / F-17）。Cloud Functions は使わない（[0001](0001_no_cloud_functions.md)）ため、依頼・承認はアプリと Firestore のセキュリティルールだけで実現する必要がある。

## 決定

- **依頼は、許可されていないアカウント自身が作る。** ドキュメント ID は自分のメールアドレス（小文字）で、ルールでログイン中のメールアドレスと一致することを確認する。1 アカウントにつき 1 件だけで、作り直し・変更はできない。
- **承認は開発者がアプリから行う。** 承認するときにメモ（誰のアカウントか）と開発者にするかを決め、許可リストへの追加と依頼の削除を **1 回のバッチ** で行う。却下は依頼の削除だけ。
- **アプリから許可リストにできるのは追加だけ。** 許可済みのアカウントのメモ・開発者の変更と削除は、これまでどおり Firebase コンソールから行う。
- **アクセス権限エラー画面では自動でサインアウトしない。** ログインしたまま依頼でき、「もう一度確認する」で承認されたかを確かめられるようにする。サインアウトは「別のアカウントでログイン」を押したときに行う。

## 理由

- 依頼の ID をメールアドレスにすると、本人のアカウントでしか作れず（なりすましできない）、同じ人が何件も依頼を作ることもない。メールアドレスはログインしたアカウントのものを使うので、打ち間違いもなくなる。
- 承認をバッチにすると、「追加されたのに依頼が残る」「依頼が消えたのに追加されていない」といった中途半端な状態にならない。
- 変更・削除までアプリでできるようにすると、誤操作で自分や家族を締め出したり、開発者の権限を外したりするおそれがある。頻度も低いので、まずは追加だけに絞る。
- 依頼を作るにはログインしている必要がある（ルールでメールアドレスを確かめるため）。表示した時点でサインアウトしてしまうと依頼できないため、自動サインアウトをやめた。許可されていないアカウントは、ログインしたままでもデータを読み書きできない（ルールで拒否される）ので問題はない。

## 影響

- 許可されていないアカウントでも、自分の依頼の作成と確認だけはできる。開発者は許可リストと依頼の一覧を読める。
- 許可されていないアカウントでアプリを閉じると、次に開いたときもアクセス権限エラー画面になる（承認されていれば在庫一覧が開く）。
- どの Google アカウントでも依頼は作れる。知らないアカウントからの依頼は、開発者が却下する。
- すでに許可リストにあるアカウントの依頼を承認しようとすると、許可リストの変更にあたるためルールで拒否され、承認は失敗する（許可済みのアカウントは、もともと依頼を作れない）。
